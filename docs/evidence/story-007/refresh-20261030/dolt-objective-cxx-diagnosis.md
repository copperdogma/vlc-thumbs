# Mixed language compiler tags through a build accelerator

First normal macOS build fails at skins2 macosx_dragdrop.mm, Error127. Generated make invocation supplies `doltlibtool --tag=OBJCXX --tag=CXX --mode=compile clang++ ...`. Current upstream's skins2 Makefile unconditionally sets per-target LIBTOOLFLAGS=--tag=CXX; current Automake emits OBJCXX for .mm. Current upstream Dolt accepts CXX, preserves unrecognized OBJCXX, and calls its compiler wrapper with OBJCXX as argv0. No contribution patch edits these files. The corresponding source files are unchanged from source10 base to pinned current master.

General class: two conflicting language-selection options crossing a compiler wrapper. Standard solution is one correctly selected language tag or delegation to full libtool for unsupported language combinations, rather than treating a flag as compiler executable. GNU primary references: https://www.gnu.org/software/libtool/manual/html_node/Tags.html and https://www.gnu.org/software/automake/manual/automake.pdf (Objective C++ support). Exact local witness: `make -C source/build-macosx/modules -n V=1 gui/skins2/macosx/libskins2_plugin_la-macosx_dragdrop.lo` and normal-build.log.

Proposed minimal source fix: teach Dolt tag classification to handle OBJCXX (and OBJC consistently) as recognized compiler tags, removing them before passing compiler argv. Alternatively remove skins2's global explicit CXX tag and rely on Automake's correct source-language selection if its link invocation remains CXX. Both preserve skins2, native macOS, Metal, and production source behavior. Root review required before applying source changes. No retry or feature disable performed.

Remaining uncertainty: whether current official CI Automake version avoids the duplicate-tag path, and whether other mixed-language targets expose it. Verify chosen fix on the exact failing target with V=1 before full continuation.

Selected adaptation after root review: use ordinary full GNU libtool through the standard GNU make command-line variable `LIBTOOL=$(top_builddir)/libtool`; leave submission source unchanged. Exact failing-target V=1 proof passes in4.02s and shows both language tags accepted with the original clang++/ObjC++ flags. Follow-on normal make and VLC.app package pass; conventional codesign validation passes. Normal check and distcheck use the same recursive make override. This changes the build acceleration route only and does not disable skins2, Metal, Sparkle or tests. The unused proposed Dolt patch is retained as private investigation material and excluded from submission.
