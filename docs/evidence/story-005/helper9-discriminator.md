## Preserved failures and reproducibility limits

The initial driver put `--worker` after `--input`; the helper correctly returned invalid_arguments. Corrected flag order is a driver repair. The private build first used unnecessarily strict `patch -F0`; a changed fallthrough context failed. Pinned contrib `main.mak:487` uses `patch -fp1` with normal fuzz, which applied all selected patches. Configure then failed because relocated host clang lacked SDK headers; adding explicit host SDK CFLAGS fixed that environment error. Logs/manifests retain both failures. No product workaround or retry loop was added.

Scratch remained about280MiB, free space about3.4GiB, above the1GiB reserve. Tests use isolated process groups; this is not a helper watchdog/NAS cancellation qualification. Decoder comparisons use a separately installed FFmpeg8 reference, not the candidate libraries. LGPL-2.1-or-later FFmpeg source and GPL-2.0-or-later helper notices were retained. Static dependency closure, corresponding source, supported versions, and public distribution remain unqualified.

## Required next route decision

This discriminator supports investigating the already-listed retained-helper route. It does not provide shipping dependency integration. A conventional clean recipe must either maintain a dedicated configured helper-private dependency variant or adopt the minimal metadata patch across normal contrib and accept broader plugin regression scope. Host-specific BSD archive replacement is diagnostic evidence only. See `helper9-build-integration-options.md` for ordinary Automake/Meson installation, macOS packaging/signing and variant tradeoffs.

A master consumer should obtain selected ES input identity through the existing core API under the player lock where available, then explicitly validate mapping; string parsing/ordinal inference alone is insufficient. The current copied helper still accepts count-guarded ordinals and targets the previous time policy. Native bridging, finite preparation priority, bounded cancellation, sampled freshness/NAS responsiveness, cache/restart and native hover proof remain required. No architecture or submission-readiness claim follows from these results.
