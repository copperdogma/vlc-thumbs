# Distribution revision contamination from an ancestor checkout

General problem: Git auto-discovery can attribute an extracted distribution under an unrelated repository to that parent checkout. Automake deliberately builds an archive in read-only VPATH source; see [official checking-the-distribution contract](https://www.gnu.org/software/automake/manual/1.16.2/html_node/Checking-the-Distribution.html). The pinned VLC src/Makefile.am:766 always invokes git -C top_srcdir describe, falling back to the distributed revision.txt only when discovery fails.

Actual 070541Z distcheck: its initial GNU-sed distribution/archive and minimal configure completed; compilation failed when stamp-revision tried to move revision.tmp into read-only source revision.txt. Read-only attribution confirms Git in the extracted archive returns wrapper repository 36dc5ee, while its shipped revision.txt contains 4.0.0-dev-39282-g2e358f3098. This difference causes the overwrite. This does not demonstrate a feature regression.

[Git's official GIT_CEILING_DIRECTORIES documentation](https://git-scm.com/docs/git/2.45.1.html) provides conventional control of parent-directory discovery. A bounded read-only smoke with the independent output directory as ceiling keeps the actual independently cloned source's correct repository and revision, while extracted archive Git discovery fails and the unchanged upstream fallback can retain the distributed revision. Exact commands/results are in distcheck-git-discovery-smoke.json.

Proposed repair: scoped GIT_CEILING_DIRECTORIES for this distribution operation, no source patch, permissions weakening, synthetic repository, or source-check change. No further recipe retry before root scope approval. Failed run and first archive are retained with distinct provenance, including generated gettext delta.
