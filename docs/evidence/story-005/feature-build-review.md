## Material findings

**B1 — Meson `auto` is implemented as mandatory dependencies on macOS.** `bin/meson.build:117–124` checks the feature object's `.allowed()` but each FFmpeg dependency omits `required`. Therefore desktop macOS with default `timeline-preview=auto` and missing/older FFmpeg9 fails configuration rather than omitting this optional helper. The option default is `auto` (`meson_options.txt:858`). This is a source-derived finding, not a reproduced Meson run. Pass the platform-constrained feature value as `required` to dependency lookup, then create the helper/test only if every dependency is found. Explicit `enabled` should still fail clearly. Meson's documented feature contract maps `auto` to optional lookup; its dependency default is required. [Meson build options](https://mesonbuild.com/Build-options.html#features), [dependency reference](https://mesonbuild.com/Reference-manual_functions.html#dependency).

**B2 — Minimal distcheck policy needs an explicit helper decision.** Autoconf defaults the helper on for macOS with the VLC executable (`configure.ac:2882–2894`), independently of `--disable-avcodec`, `--disable-avformat` or `--disable-swscale`. The upstream root's `AM_DISTCHECK_CONFIGURE_FLAGS` disables those decoder dependencies (`Makefile.am:30–41`) but does not disable the new helper, which still requires FFmpeg9. A minimal macOS distcheck without a selected FFmpeg9 prefix therefore now gains an unrelated hard dependency. The normal contrib-enabled feature build can succeed; that does not establish the minimal distribution branch. Recommend an explicit helper-disabled minimal distcheck, plus a distinct feature-enabled configured helper/native target using the selected patched contrib. Whether macOS Autoconf default-on remains the desired upstream policy is a root/maintainer choice; unlike Meson's advertised `auto`, this branch explicitly selects `yes`. No configure/distcheck execution was done here.

**B3 — Python test prerequisite has no clear missing-tool check (lower priority).** `configure.ac:2890` uses `AC_PATH_PROG` without checking its result, while `bin/timeline-preview/Makefile.am:15–17` unconditionally uses it in `check-local` whenever the helper is enabled. A missing Python3 can consequently reach an invalid test command. Runtime helper execution does not require Python. Either produce a clear check-time/configure-time diagnostic or explicitly skip these tests with a visible reason. The source-only fixture guide correctly declares Python/FFmpeg/FFprobe requirements.

Static branch consistency note: an explicit `--enable-timeline-preview --disable-vlc` checks dependencies and sets BUILD_TIMELINE_PREVIEW, although its actual Automake executable remains gated out by BUILD_VLC; Meson rejects that explicit combination. This is not a demonstrated packaging failure, but should be made consistent or documented alongside the configuration repair.

## Inspected boundaries that are sound in this freeze

- macOS desktop gate: Autoconf uses HAVE_OSX; Meson uses have_osx and build_vlc. Upstream platform detection distinguishes iOS/tvOS/watchOS/visionOS. Defaults do not add the helper target on non-macOS. Non-macOS and cross branches were only statically inspected, not run.
- Installed target: `bin/timeline-preview/Makefile.am:1–10` adds `vlc-timeline-preview` to pkglibexec_PROGRAMS only under BUILD_VLC + BUILD_TIMELINE_PREVIEW. The common bin Makefile initializes that list once and cache/preparser/helper append to it; this preserves static-plugin and dynamic-plugin target coexistence rather than overwriting earlier executables.
- Production/test separation: `modules/gui/macosx/Makefile.am:891–901` lists only the ten production context/service/worker/cache/scheduler files. TestSupport and test helper are absent. `tests/Makefile.am` gates all native bundles under ENABLE_MACOSX_UI and ENABLE_MACOSX_XCTESTS, places the context stubs in a separate focused bundle, and uses check_PROGRAMS for the C fault helper. Absolute test helper/core rpaths belong to test products; they are not production helper lookup paths.
- Distribution inputs: helper C source is a target source; PROTOCOL/test.py and the three portable fixture recipe/README files are explicitly EXTRA_DIST (`bin/timeline-preview/Makefile.am:11,21–24`). Native test/context files are registered target sources. Root EXTRA_DIST includes contrib/src recursively (`Makefile.am:90–92`), covering patch sources. No test Python bytecode directory is explicitly registered. This is source-list review, not proof of an emitted source tarball; final tar inventory must confirm additions and exclude generated/private artifacts.
- Static closure: the conventional contrib FFmpeg recipe enables static and disables shared libraries (`rules.mak:17–18`). Helper Autoconf linkage uses PKG_CHECK_MODULES_STATIC private dependency closure and has no VLC-core LDADD; Meson requests static dependencies. The prior normal-helper manifest reports only system framework/libSystem dynamic references, consistent with the selected contrib archives. `pkg-config --static` is closure selection, not universal enforcement against an arbitrary external prefix that also contains dylibs; use the explicit verified contrib environment and inspect final linkage. The incoming flat patch/final helper require fresh binary receipts before this prior closure evidence can be carried forward.
- Packaging: `package.mak:27–28` recreates VLC.app, so disabled-helper rebuilds cannot retain an old staged helper. Lines82–84 copy the enabled installed target beside the main executable. `VLCThumbnailService.m:197–198` resolves only that sibling name, without a PATH/helper override. The static helper needs no libvlc rpath rewrite. This assumes the final linkage remains system-only; otherwise the package recipe needs dependency/rpath handling rather than silently relying on host libraries.
- Signing: `codesign.sh` is fail-fast (`set -e` at19), signs the helper if present at152–154, then signs/verifies the app. The enabled copy step fails if the installed helper is absent. This is correct source ordering; the latest feature app/helper copy/signature/relocation has not been acquired, so source inspection is not signing proof.
- Runtime option compatibility: the macOS module registers existing `macosx-timeline-previews` (default true). Context/UI retain effective inherited runtime configuration precedence rather than replacing explicit CLI values with saved preferences. Build disablement and UI preference disablement are different controls; a missing disabled-build helper must fail gracefully in the service.
