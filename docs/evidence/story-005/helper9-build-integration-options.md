## Version, licensing and deployment hazards

- Selected installed pkg-config versions: avformat63.1.100, avcodec63.1.100, avutil61.1.100, swscale10.1.100. The static closure includes zlib, GSM, LAME, OpenJPEG, math/pthread and Apple AudioToolbox/VideoToolbox/CoreFoundation/CoreMedia/CoreVideo/CoreServices frameworks. Use exact selected `.pc` metadata and complete corresponding-source/configuration inventories; four FFmpeg archive hashes alone are incomplete.
- Local helper source declares GPL-2.0-or-later; existing Matroska patch context declares LGPL-2.1-or-later (`patches/README.md`). FFmpeg explains that optional GPL components can change its effective license and that supplied source must correspond to binaries and modifications. [Official FFmpeg licensing guidance](https://ffmpeg.org/legal.html). Its dynamic-link compliance checklist is one suggested LGPL route, not a finding that this GPL helper's static-link assembly is distribution-qualified. Inspect actual FFmpeg configuration plus every linked dependency and retain source, patches, build recipe and notices before public binaries. No public compliance clearance is claimed.
- Pinned macOS environment defaults to10.13 (`extras/package/macosx/env.build.sh:4`) and exports architecture/SDK/deployment flags at179-182. Actual selected arm64 `libavutil.a` object load commands inspected here report minOS11.0, SDK26.2 (some SDK n/a), appropriate to an arm64 slice rather than proof of an Intel10.13 binary. Use the shared build environment, avoid copying the old helper's fixedarm64 command, and qualify each intended architecture/minOS separately. Current host/Xcode/SDK27 success does not establish execution on oldermacOS. Availability guards and library object floors need audit.
- This pass does not prove FFmpeg9 helper compilation, Matroska stable identity, edited/negative-CTTS movie-time correctness, timestamp provenance, network/watchdog recovery, persistent-cache freshness, native hover responsiveness or maintained fork acceptance. The separately owned helper9 discriminator is experimental substrate evidence only; it does not supply build-system integration, clean dependency reproduction, signing/packaging, licensing or cross-version qualification.

## Decision boundary

Lowest-maintenance conventional route is an ordinary installed helper target using selected contrib, with a minimal accepted/maintained source-level FFmpeg metadata patch if identity truly requires it. If plugin-wide behavior must stay untouched, name and budget a genuine private dependency target rather than accepting host-specific object surgery. Root must decide contribution fit and dependency scope before either implementation.
