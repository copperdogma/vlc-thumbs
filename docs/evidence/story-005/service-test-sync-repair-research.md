# Asynchronous completion and pipe fault-fixture repair

The quiet independent suite `reproduction-native-final-20261006T063243Z.log` repeated the inherited proactive-coverage failure: after a fixed 2.5-second wait, six jobs completed, request seven was active, and one reusable worker remained ready. The whole method took 60.857 seconds, including other fault/watchdog cases. The existing condition-based quiescence test passed. Root approved replacing only this sleep with the already established five-second bounded completion condition, preserving the finite-count and following fairness assertions. Production scheduling and worker deadlines are unchanged. Apple's [asynchronous XCTest guidance](https://developer.apple.com/documentation/xctest/asynchronous-tests-and-expectations) favors bounded waits for completion rather than a guessed sleep.

The same quiet suite's pipe test accepted its seven-byte write about 0.012 seconds after a 4096-byte fill first reported EAGAIN. Subsequent cancellation and byte-drain assertions cascaded: the queued 50 ms invalidation had not necessarily run when an epoch-1 case began. The original test reused one worker/epoch across all scenarios and assumed pipe capacity stayed fixed after an EAGAIN observation.

[POSIX write](https://pubs.opengroup.org/onlinepubs/9690949599/functions/write.html) distinguishes request size and available space, so EAGAIN for one request size does not prove a smaller request cannot fit. [Published Apple XNU pipe implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/sys_pipe.c) also permits expansion of a nonempty pipe depending on changing global pipe-buffer allocation pressure. Its published size table ends at PIPE_SIZE times four; [pipe.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/pipe.h) defines PIPE_SIZE as 16384, giving a 64 KiB buffered capacity ceiling in that source. This is a documented Darwin fixture assumption, not a universal POSIX or future-kernel guarantee.

A bounded local C discriminator created and closed 32 pipes, filled using 4096-byte writes, then attempted the seven-byte command. Every tiny write also reported EAGAIN; the observed filled capacity was 512 bytes in each case. `work/story005-pipe-causal-probe/{probe.c,results.jsonl}` preserves the probe. It did **not** reproduce the quiet failure. Dynamic capacity growth is compatible with the observed failure and the primary source, but is not established as its exact runtime cause.

Root approved test-only scenarios that use a 256 KiB no-reader payload for timeout/cancellation, exceeding the published Darwin buffer ceiling even if the pipe grows. Each timeout, cancellation, disconnected-reader and slow-drain scenario owns a fresh worker and pipe. Invalidation is explicitly joined with a bounded wait before cancellation-case cleanup, eliminating cross-scenario epochs. Existing 0.15/0.75/2-second bounds remain; the successful slow drain still verifies all 256 KiB byte-for-byte. No product/helper changes or deadline inflation are introduced.

Exact one-file diff/hash and compilation are recorded in `service-test-sync-repair-receipt.json`. Independent narrow review and one normal two-selector run precede the selected final whole-suite run. Native service/cache observations separately confirmed that replacing the isolated cache symlink with an actual owned directory produced a version-5 seven-sample/seven-target inventory; that setup correction is unrelated to these test-only failures.
