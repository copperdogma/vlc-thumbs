# Master existing hover-panel feature candidate

The UI lane modifies ten files in the shared isolated clean-pinned candidate: progress slider header/source, main video controller's explicit fade hook, Simple Preferences header/source/XIB, macOS option registration, `tests/VLCTimelineHoverTest.m`, and two isolated headless reentrancy test/support files. It does not modify the qualified app/source, controls bar seeking/scroll/keyboard actions, build lists, or remote state.

The existing slider remains the sole owner of its existing nonactivating hover panel. The panel retains pointer time and adds preview pixels plus a localized complete actual-keyframe/status template. Eligible requests pass the immutable context directly into `VLCThumbnailService -requestForContext:time:completion:`; its token is `NSUInteger`. The main-thread callback requires both the unchanged request presentation serial and context generation. Nil/error images remove pixels. Ineligible or disabled previews retain ordinary time hover.

One tracking area remains owned by the slider and is hosted by its direct superview. Its band is 32 points high centered on the actual bar, constrained to the bar's horizontal range and clipped to the direct parent's bounds. The slider frame, hit testing and existing bar-based fraction remain unchanged. Reparenting removes the old parent's area; frame/bounds/window changes rebuild it. Drag, disable, indefinite state, hiding, inactive app, context/configuration changes and window lifecycle cancel the pending presentation. The video controller explicitly marks controls unavailable before its fade begins and available when showing controls. No private ancestor inspection, global event monitor, duplicate popup or legacy fullscreen controller was added.

The tracking choice follows [Apple's rect contract](https://developer.apple.com/documentation/appkit/nstrackingarea/rect) and [inVisibleRect behavior](https://developer.apple.com/documentation/appkit/nstrackingarea/options/1532332-invisiblerect): the latter ignores an explicit rect. Root approved one area in direct-parent coordinates with no inVisibleRect flag, allowing the expanded hover band without enlarging seek hit testing. Actual AppKit pointer/occlusion behavior still needs native proof.

The public option remains the existing `macosx-timeline-previews`, default on. Simple Preferences loads/saves this option through the normal controller path; Cancel does not save. Both Simple and Advanced Preferences already announce `VLCConfigurationChangedNotification`, which the context and slider observe. The UI reads the effective inherited variable, preserving explicit CLI precedence over saved config. A configuration change while hovering restores the currently appropriate ordinary/preview hover in that same window. No redundant custom preference notification remains. The internal checkbox outlet name is unrelated to the public option. All added translated templates are in existing POTFILES-listed source paths, so no localization-list entry is needed.

Focused source checks: the four changed Objective-C/C translation units pass syntax checks against the generated candidate configuration; existing preferences deprecation warnings remain. The pure UI test source runs through a standalone Foundation/AppKit harness: four methods, 26 assertions, covering centered geometry, direct-parent conversion/clipping, unchanged seek frame, actual-bar fractions/endpoints and delayed context/presentation rejection. The XIB compiles successfully; its warning/notice payload is exactly equal to the clean baseline's, including no new checkbox layout issue. The registered XCTest target still belongs to the build owner. Exact commands and source hashes are in `ui-feature-candidate.json`; raw focused receipts are ignored under `work/story005-ui-checks`.

Native interaction is deferred while the Mac is locked. These checks do not establish actual pointer hover, all four surfaces, key/scroll/reader behavior, saved/CLI preference interaction in the live app, fade/drag/context races, provisional-source deadlines, playback overhead or submission readiness. Those remain the frozen verification plan's gates. No app installation or public distribution was performed.

Snapshot refresh may synchronously post a context notification. The slider obtains the snapshot before establishing a new hover (and then checks availability/geometry), and completion obtains its refreshed snapshot before reading the presentation guard. An isolated test executes the actual slider methods with injected synchronous notifications and no window creation: both regressions plus the four pure methods pass, six methods/32 assertions. A disposable counterfactual restoring the bad presentation-before-snapshot ordering fails the new-hover assertion; no product source was reverted. The narrow doubles are linked only into the separate focused target. This is headless source behavior, not native UI proof.

At the bar right edge, the pointer label retains the full duration while the preview request clamps to `MAX(0, duration - 1)` microseconds. The service still rejects requests at or beyond duration; this introduces no frame-rate or actual-sample-time assumption. Four boundary assertions cover the exact end, middle, one-microsecond duration and zero duration.
