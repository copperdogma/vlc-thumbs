# Ideal-first methodology — VLC local contract

The Ideal describes the perfect product experience and execution experience.
The spec names current constraints, the compromise each forces, its limitation
type, detection/evolution path and what can simplify when the limit changes.
Use the Ideal as a feature filter. A candidate technique is not a measured
constraint; do not invent failures to justify architecture.

Mutable operational truth lives in state, story files and the eval registry.
`make methodology-compile` joins labeled `ideal:req:*` requirements, `spec:N`
headings, story frontmatter and state into graph and stories index. The portable
compiler supports a small scalar/inline-list YAML subset; use inline reference
lists in state. Graph and index are generated views.

Categories carry substrate and phase: climb for a real unmet capability; hold
for a qualified floor; converge when a deletion gate passes. No product category
can claim hold merely because setup passed. AI execution compromises need a
measured deletion eval or explicit deferral/trigger; ecosystem/physics/legal
constraints have evolution paths. This product does not require AI at runtime.

Root eval defines the complete user outcome. Child evals may isolate observed
failures or explicitly planned capability questions. No absent runner counts as
failure. Stories package actionable work; Draft is honest when source/build/UI
substrate is unverified. Relevant ADRs record decisions when evidence supports
one; source-project ADR numbers do not become local decisions automatically.

`/init-project` seeds intake/Ideal/spec; `/setup-methodology` installs the full
package. `/triage` compares gaps, `/align` propagates meaningful changes, and
the story/eval skills own build and proof. Keep process proportional to the
project. Simplify process when a measured lighter approach meets the quality bar.
